## 확인된 최우선 근본 원인·수정

**반복 원본 확인 상태가 문항 전환 시 무조건 초기화되는 문제.** 기존 `selectQuestion()` 캐시·네트워크 응답 경로 모두에서 `state.pdfTab='question'`으로 강제 초기화했다. 따라서 실제로 같은 원본 대본 10쪽을 공유하는 35회 25→26 이동 시 다시 시험지 9쪽을 표시하여 모바일/데스크톱에서 매번 대본 탭 선택과 음원 위치 이동이 필요했다. 원본 진입 후 정답표/대본 선택도 최소 2클릭이었다.

1. `retainedSourceTab(previous,next,tab)`으로 **같은 회차·같은 영역이며 다음 문항에도 출처 파일이 있을 때만** 정답표/대본 탭을 유지한다. 문항 전환시 PDF URL과 물리 페이지는 **다음 문항의 실제 메타데이터를 기반으로** 다시 계산한다. 36회 듣기→읽기, 없는 대본, 회차 변경에서는 시험지로 안전하게 복귀한다. F3 최초 목록·bundle·선택 흐름에 새 네트워크 요청 없음.
2. 문항 상단에 `시험지 원본`, `정답표 원본`, 듣기에서만 `대본 원본`, `전체 듣기 음원` 직접 버튼 추가. 모바일은 기존 원본 dialog를 열고 원하는 실제 탭/음원 영역을 곧바로 스크롤·키보드 포커스한다. **키보드 초점·대상 URL에 없는 정보는 만들지 않음**. PDF 탭은 원본 창에서 스크롤 중에도 접근 가능하게 sticky 처리. 기존 AI 근거·경고·승인 버튼 및 모바일 최소 44px 버튼 유지.
3. 이전에는 36회 듣기에서도 하드코딩된 35회 25/26,27/28,29/30 공유 번호가 표시될 수 있었다. 35회 source-scoped guard로 제한하고, 36회 서버가 지원하지 않는 음원 구간 저장/검증 UI를 숨겼다. **36회 전체 음원 청취는 계속 가능하며 구간·시간은 미기록/미지원으로 표현**. 35회의 음원 후보는 후보로만 표기한다.
4. 35회 공유 원본 대본의 편집이 반대쪽 문항에 자동 적용되지 않음을 대본 힌트와 음원 공유 경고에 명시. 사람 승인·AI 검토 완료·음원 구간 검증 상태를 서로 혼동하지 않도록 보호한다.
