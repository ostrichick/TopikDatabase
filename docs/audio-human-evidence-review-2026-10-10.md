## 실제 확인한 P1 원인 및 조치

기존 `save_audio_segment()`는 `{version,start_ms,end_ms,status}`만 받아 `verified`가 되려면 단순히 후보 행이 **존재하기만** 하면 됐다. 따라서 후보 20,000–27,000ms를 저장한 후 HTTP API로 **21,000–27,500ms**를 곧바로 `verified`로 보내도 두 문항이 승인되는 안전성 결함이 있었다. 기존 `tests/test_audio_segments_api.py`에서도 이를 정상 200으로 주장했다. 화면 내부의 전체 구간 재생 검사는 **브라우저 클라이언트만의 조건**이므로 서버 승인 안전성을 보장하지 않는다. 기존 수동 음원 이력에는 `before/after/source_sha256`뿐이고 사람이 무엇을 청취·판단했는지 메모가 없었으며 질문 검수 이력과 섞이지 않도록 음원 기록을 별도 확인할 UI가 없었다.

1. **서버 fail-closed:** `verified` 요청은 기존 두 짝 문항이 모두 동일한 **현재 저장된 `candidate`의 정확한 시작/종료값**을 갖고 있을 때만 허용한다. 양쪽 음원 버전 CAS, MP3 원본 크기·SHA, 미검수 공유 대본의 출처 파일/페이지/문자 일치도 원자적 트랜잭션에서 재확인한다. 후보와 다른 시각이나 `verified→verified` 중복 승인·역방향 변경은 409. 구간 변경은 별도의 `candidate` 재저장과 새 사람 검증이 필수다.
2. **사람의 명시적 선언:** 35회 `verified` 요청에 정확한 `human_evidence` JSON(원본 직접 청취/시작 경계/종료 경계/대본 4개 명시적 true, **공유 쌍이 실제 등록됐을 때만** 짝 문항 확인 true·단일 문항이면 false, **20~2000자 구체적 메모**)이 반드시 있어야 한다. 미등록 짝 확인을 거짓으로 강요하지 않으며 UI도 단일 문항에서 짝 확인 항목을 숨긴다. 누락·형식 오류는 400, 후보 저장은 변경 없이 가능. 자동 재생 완료 이벤트·AI·음원 파형 결과를 사람 승인으로 **추정하지 않는다**. 브라우저의 end-to-end 재생 상태는 추가 사용성 안전장치일 뿐이고 사람의 청취 사실을 증명하지 않는다.
3. **원자적 독립 검수 이력:** 검증 시 동일 원본 구간만 양쪽 audio_segments에 반영하며, 기존 `review_records`에 각각 `manual_audio_boundary_35` + source SHA + before/after + typed `human_evidence` + 시각을 기록한다. 해당 기록은 **사람이 입력한 선언**이며 독립적인 신원·청취 검증은 아니다. 문항별 `question`·`transcript` 승인 상태/이력과 버전은 자동 변경하지 않는다. 두 번째 이력 쓰기 중 실패하면 양쪽 음원 상태·버전·이력을 전부 롤백한다. DB 스키마 변경이나 36회 마이그레이션은 없음.
4. **UI 대조·반복·근거 입력:** 기존 오디오 플레이어의 원음 구간 재생에 ‘같은 구간 다시 듣기’, ‘시작/종료 경계 전후 3초’ 버튼을 추가했다. 경계 청취나 전체 플레이어 seek만으로 검증 완료 버튼을 활성화하지 않는다. 원본 대본 PDF 위치(실제 저장 페이지 10/11/12, 없으면 미기록), 짝 문항으로 키보드 이동, 16px 모바일 근거 폼, 현재 후보/근거 불명/사람 선언 기록을 구별한다. 검증 후 입력폼 선언은 초기화하지만 저장된 이력은 `review_records`에서 다시 조회할 수 있다.
5. **F3 비용 유지:** 개별 상세 응답에 최신 음원 상태·유효한 명시적 선언·최근 음원 전용 기록을 제공한다. 목록 bundle은 종전 `review_records` 조회 한 번에 `audio_segment` 행도 읽어 각 문항별로 묶되 **질문 리뷰 버전은 question record만 계산**한다. 단일 SQL 경로를 유지하고 음원별 N+1 조회를 추가하지 않는다. 자동 후보/클립 추출 로그는 사람 청취 완료로 보여주지 않는다.

## 세 장기 목표 재평가·다음 가장 중요한 문제

- **UI/UX·가독성:** 같은 화면 안에서 실제 35 MP3 시작/끝 대조·반복·원본 PDF·근거 작성·짝 문항으로 연결하는 동선 제공. 모바일 320/390과 데스크톱 1366 확인.
- **검수 의사결정:** 저장 상태 `candidate`와 독립적 `human_evidence` 선언/미확인, audio 검증과 question/transcript 승인을 명확히 분리. 검증된 파일 SHA만으로 사람 청취 완료 주장 금지.
- **간소화:** 기존 POST/버전/공유잠금/한 트랜잭션과 `review_records`를 재사용, 신규 DB 테이블·원격 요청·중복 집계 없이 근거 추가. 테스트는 기존 자체 정리형 PostgreSQL 자동화에 통합.

**다음 우선순위:** 실제 사람이 세 공유 MP3 후보 구간을 직접 듣고 **시작·종료 경계와 대본 발화의 정확성**을 책임 있게 검수하여 근거를 입력할 운영 절차 확립. 그 전에는 자동 검증 완료·청취 정확도 단정 금지. 또한 추후 확인자의 구체적 식별과 감사 provenance 강화를 위해 로컬 `local_reviewer` 고정 식별자를 인증된 개인 신원으로 바꾸는 보안/권한 계약을 별도 검토할 수 있다(이번 범위에서 사용자 인증 시스템 임의 추가하지 않음).
