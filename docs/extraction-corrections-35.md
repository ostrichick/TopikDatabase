# 35회 TOPIK I 추출 보정: 문장부호 공백 및 순수 이미지

이 보정은 **제35회 TOPIK I(B형) 로컬 SQLite 시범 데이터베이스에만** 적용됩니다.
원본 시험지·답지·대본·음원, 원본 이미지가 삽입된 이전 HTML 미리보기,
정답 번호와 배점은 수정하지 않습니다. TOPIK II나 다른 회차에는 자동 적용하지 않습니다.

## 적용한 규칙

- 문장부호 `.` 또는 `,`의 다음 글자가 한글 또는 여는 괄호이고, 앞 글자가
  한글·닫는 괄호/대괄호이면 **공백 한 칸을 추가**합니다.
  예: `입니다.이` → `입니다. 이`, `네,우산` → `네, 우산`,
  `합니다.( ㉠ )` → `합니다. ( ㉠ )`.
- 소수점 `3.14`, 천 단위 `1,000`, URL·이메일, 파일 확장자, 말줄임표,
  기존 띄어쓰기·줄바꿈은 변경하지 않습니다. 혼합 라틴 문자 등 모호한
  문장과 PDF의 낱말 내부 띄어쓰기 오류는 검토자가 원본과 별도로 대조해야 합니다.
- 정규화 대상은 문항 본문(`questions.stem`), 네 보기(`choices.text`),
  공통 지시문·지문(`question_groups`), 듣기 대본(`transcripts.dialogue_text`)입니다.
  초기 추출 원문(`raw_question_text`)은 원문 추적을 위해 **그대로 보존**합니다.
- 이미지 15·16번: 각 그림과 **①②③④를 포함**하되 바깥쪽 `15.`/`16.`은 제거합니다.
  40·41·42번: 그림 자체만 남기고 시험 번호와 `(3점)`을 제거합니다.
  63·64번의 공통 이메일 그림은 처음부터 깨끗하여 변경하지 않습니다.
- 이미지 원본 PNG 여섯 개를 SQLite에 그대로 보존합니다. 수정 이미지 다섯 개는
  `-clean-v1.png`라는 새 키로 추가하고, 관련 문항 링크만 교체합니다.
  크롭은 기존 PNG의 검증된 SHA-256과 크기, 개별 픽셀 영역을 기준으로 재현되며
  그림 내용·선택지 번호를 다시 그리거나 OCR로 추정하지 않습니다.

## 기존 DB에 안전하게 적용하기

프로젝트 폴더에서 **기존 검토 서버를 종료한 다음** 다음 명령을 한 번 실행합니다.

```powershell
py -3 src/correct_pilot_35.py
```

실행 전 기존 미리보기·원본 파일의 SHA-256과 실제 DB의 문항·보기·대본·이미지
초기값을 대조합니다. 수동 승인, 반려, 검토 이력, 심지어 검토 이력 없이 변경된
본문이 하나라도 있으면 보정을 **중단**하며 데이터를 덮어쓰지 않습니다.
정상 검증 뒤 `topik-past-papers/derived/`에 `*.before-extraction-correction-*.sqlite`
이름의 전체 SQLite 백업을 먼저 생성합니다. 보정은 단일 트랜잭션에 기록되며
각 문항의 보정 전/후 값과 이미지 SHA-256, 검토 필요 상태를 이력에 남깁니다.
다른 브라우저 탭의 이전 데이터는 버전 충돌(409)을 반환하여 임의로 덮어쓰지 않습니다.
같은 명령을 다시 실행하면 새 백업이나 추가 수정 없이 완료 상태만 보고합니다.

새 파일을 처음부터 생성하는 경우에는 `py -3 src/pilot_35.py`가 두 규칙을
동일하게 적용합니다. **기존 DB를 삭제하거나 강제 재생성하지 마세요.**

## 범위와 미해결 검토

이 수정으로 초기 구조화 필드의 누락 공백 **128곳**, 이미지 **5개**가 보정됩니다.
이미지 6개 중 5개에 있던 번호/배점을 제거하며 63·64번 공유 이미지는 유지합니다.
문항별 정답·배점, 원본 파일 5개의 SHA-256, 70문항 승인 상태는 변경하지 않습니다.
자동 보정은 검토자 승인이나 원본 PDF 전체 텍스트의 정확성 인증을 의미하지 않습니다.

듣기 대본의 **단어 사이 공백**은 위 문장부호 규칙만으로 복원되지 않습니다.
35회 원본 PDF에 있는 단어 공백은 `src/transcript_35.py`의 pypdf 추출로
별도 복원하며, 기존 DB는 `src/upgrade_transcripts_35.py`를 통해 전체 백업과
검토 기록 보호를 거쳐 갱신합니다. 이미 승인하거나 수동 수정한 대본은
자동 덮어쓰지 않습니다.
