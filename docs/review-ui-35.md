# 제35회 TOPIK I 수동 검토 UI

이 도구는 **현재 PC에 저장된 제35회 TOPIK I B형** 문항 70개를 검토하기 위한 로컬 웹 화면입니다. 인터넷 공개·배포 기능은 없습니다. TOPIK II와 다른 회차는 아직 지원하지 않습니다.

## 실행

프로젝트 최상위 폴더(`TopikDatabase`)에서 PowerShell을 열고 다음을 실행합니다.

```powershell
# DB 파일이 아직 없는 경우에만 최초 생성합니다.
py -3 src/pilot_35.py

# 검토 서버 실행
py -3 src/review_ui.py
```

실행된 터미널은 그대로 두고 **PowerShell에 출력된 주소**를 브라우저에서 여세요. 기본적으로 `http://127.0.0.1:8765/`를 사용하지만, 해당 포트가 이미 다른 프로그램에서 사용 중이거나 Windows에서 연결을 거부하면 사용 가능한 로컬 포트를 자동으로 선택해 다른 주소를 출력합니다. 예를 들어 `http://127.0.0.1:53124/`처럼 나타날 수 있습니다. 주소의 포트 번호를 임의로 8765로 바꾸지 마세요. 언제나 사용 가능한 포트를 선택하려면 `py -3 src/review_ui.py --port 0`을 실행할 수 있습니다. 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 추가 웹 패키지/CDN은 필요 없습니다.

기존 DB는 `topik-past-papers/derived/035-I-B.sqlite`에 있습니다. 처음 검토하기 전 파일을 다른 안전한 로컬 위치에 별도로 백업해 두면 좋습니다. 원본 PDF·MP3·HTML과 Git 추적 파일에는 검토 작업의 수정 내용이 기록되지 않습니다.

**2026-09 문장부호·이미지 보정:** `src/correct_pilot_35.py`는 초기 추출에서
마침표·쉼표 뒤 누락된 공백을 복원하고, 그림에서 문항 번호·배점을 제거합니다.
기존 DB를 먼저 SQLite 백업한 후 적용하며 사람의 검토 기록이나 편집 내용이
있으면 자동 수정을 거부합니다. 기존 HTML 미리보기와 오른쪽의 원본 PDF,
읽기 전용 '초기 추출 원문'은 보존되므로 보정 전 띄어쓰기가 남아 있을 수 있습니다.
실제 편집 대상인 문항·보기·공통 지문·대본과 오른쪽 그림은 보정된 DB를 보여 줍니다.
자세한 내용은 `docs/extraction-corrections-35.md`를 참조하세요.

**듣기 대본의 단어 띄어쓰기 개선:** 초기 PyMuPDF 추출은 원본 PDF의
단어 사이 공백을 대부분 누락했습니다. 이제 pypdf로 원본에 표시된 공백을
추출하고 두 프로그램의 비공백 문자가 12페이지 전체에서 일치하는지 검사합니다.
기존 DB에는 서버를 종료한 뒤 `py -3 src/upgrade_transcripts_35.py`를
실행합니다. 실제 DB는 적용 완료 상태입니다. 적용 전 SQLite 전체 백업을
생성했고, 수동 검토·수정된 문항은 보존했습니다. 당시 이미 승인한 1번은
수정하지 않고 2~30번 대본만 갱신했습니다. 검수 서버를 다시 실행하고
브라우저를 새로고침하여 확인하세요. 자동 띄어쓰기 복원은 대본 내용과
음원의 일치나 한국어 띄어쓰기 완전성을 인증하지 않으므로 육안 검수는 계속 필요합니다.

## 검토 방법

1. 왼쪽에서 문항을 고릅니다. 영역(듣기/읽기), 승인 상태, 그림 포함 여부로 필터링할 수 있습니다. 승인 진행률이 상단에 표시됩니다.
2. 가운데의 지시문·공통 지문·문항·보기·대본을 확인합니다. 오른쪽 PDF에서 **문제지 / 정답표 / 대본** 탭을 바꾸거나 새 탭으로 원본을 열어 페이지를 대조합니다. 이미지 문제는 원본 그림도 확인합니다.
3. 문항 본문, 보기 네 개, 듣기 대본을 필요에 따라 수정합니다. 정답 번호·배점은 원본 답지와 일치하는 기준값이므로 이 화면에서는 수정하지 않습니다. 오류가 있으면 **반려 사유**에 문제 번호와 근거를 기록하세요.
4. **임시 저장**은 변경 내용을 남기고 `needs_manual_review` 상태로 둡니다. **검수 승인**은 별도의 확인창 없이 한 번 클릭하면 저장되며, 저장 성공 후 다음 번호의 문항으로 자동 이동합니다(마지막 70번은 현재 화면 유지). 저장에 실패하면 이동하지 않고 입력을 유지합니다. **반려**는 사유를 반드시 입력하고 `rejected`로 기록합니다. 모든 실제 변경은 이전·새 값을 SQLite 검수 이력에 남깁니다.

`Ctrl+S`는 임시 저장입니다. 다른 문항으로 이동하거나 탭을 닫을 때 저장하지 않은 변경이 있으면 확인 메시지가 나옵니다. 다른 탭에서 먼저 수정된 문항은 서버가 HTTP 409 충돌을 반환하며, 현재 입력을 자동 덮어쓰지 않습니다. 원본을 다시 불러올 때 현재 입력이 버려진다는 확인을 거칩니다.

### 듣기 문항별 음원 구간 검수

듣기 1~30번은 오른쪽 **듣기 음원 · 문항별 구간 검수**에서 원본 전체 MP3를 들으면서 시작·종료 시각을 초 단위(소수 셋째 자리까지)로 확인·수정합니다. 원본 음원 길이를 불러오기 전에는 재생·저장을 활성화하지 않습니다. 시작 시각은 0 이상, 종료 시각은 시작보다 크고 원본 길이를 넘지 않아야 합니다. 35회 시범 DB에는 침묵 감지로 추정한 **미확정 후보 27개가 30문항에 연결**되어 있습니다. 이것은 음성·대본 일치를 검증했다는 의미가 아닙니다.

1. **설정 구간 듣기**를 누르면 전체 음원에서 시작 시각으로 이동해 재생하고 종료 시각에 일시 정지합니다. 중간에 재생을 멈추거나 위치를 건너뛰면 청취 완료로 인정하지 않습니다.
2. **후보 구간 저장**은 `candidate`로 기록합니다. 저장만으로 검증 완료 상태로 전환되지 않습니다. 시작·종료를 바꾸면 이전 청취 확인이 무효화됩니다.
3. **청취 후 구간 검증**은 같은 후보 구간을 처음부터 끝까지 들은 경우에만 활성화됩니다. 버튼을 직접 눌러 `verified`로 저장합니다. 문항 본문·대본의 검수 승인과 음원 구간 검증은 별개입니다.
4. 검증된 구간만 **검증 구간 MP3 추출** 버튼을 눌러 파일로 생성할 수 있습니다. 서버가 제공한 추출 파일 주소가 있을 때만 링크가 표시됩니다. 원본 전체 음원은 계속 재생할 수 있습니다.

시작·종료 시각의 후보 저장·검증은 기존 검수 토큰을 사용하는 로컬 API에서 처리합니다. 다른 탭에서 구간을 먼저 변경하면 충돌을 알리고 현재 입력을 자동으로 덮어쓰지 않습니다. **25·26번, 27·28번, 29·30번은 하나의 공통 대화를 공유하며 해당 쌍의 구간 저장·검증이 두 문항에 함께 적용됩니다.** 원본에서 공유 대화 전체의 시작과 끝을 확인하세요.

## 지원 범위와 제한

- 70문항, 보기 280개, 정답 70개, 듣기 대본 30개, 그림 6개를 표시합니다. 그림은 7문항에 연결됩니다.
- 듣기 15·16번은 **이미지 보기**이므로 선택지 텍스트가 비어 있는 것이 정상일 수 있습니다. 반드시 그림과 PDF를 확인하세요.
- 공통 지시문·공통 지문은 여러 문항에 공유되는 원본 추출값으로 **읽기 전용**입니다. 수정이 필요하면 해당 문항을 반려하고 메모에 남기세요. 이 UI에서는 공유 지문 자체를 편집하지 않습니다.
- 원본 전체 파일은 보존했습니다. 네 가지 무음 임계값으로 구간 후보를 자동 추정하고, 별도 폴더에 검수 전 MP3 27개를 출력했습니다. **후보의 문항 배정과 발화·대본 일치는 자동 인증되지 않으며**, 사람이 구간을 듣고 확정한 뒤에만 최종 MP3로 내보냅니다. 자세한 근거와 파일 위치는 `docs/audio-splitting-35.md`를 참고하세요.
- 초기 HTML 미리보기의 `audio_and_transcript` 경고는 **당시 추출 기록**이며, 현재 DB에는 음원과 대본이 연결되어 있습니다.
- 검수 승인은 사용자의 육안 확인 결과이지 NIIED 공식 인증이나 공개 재배포 허가를 의미하지 않습니다.

## 저장 및 안전장치

수정은 **SQLite DB에서만** 이루어집니다. 검토 화면은 정답 번호·배점·원본 파일·이미지 바이너리를 바꾸는 API를 제공하지 않습니다. 한 번의 저장은 문항 내용과 검수 이력이 함께 기록되는 단일 트랜잭션입니다. 검토 후에도 `py -3 src/pilot_35.py`를 재실행하면 기존 DB를 덮어쓰지 않고 검토 상태를 유지합니다.

서버는 `127.0.0.1`에만 바인딩되며, 요청의 Host/Origin을 검사하고 수정 요청에는 별도 검수 토큰을 요구합니다. 사용자의 PC에서 실행하는 로컬 도구이며 외부 네트워크에 배포하지 마세요. 원본 PDF·음원·대본 및 이 자료가 담긴 DB를 GitHub나 공개 서버에 업로드하려면 권리자의 허용 범위를 먼저 확인해야 합니다.

## 테스트

```powershell
py -3 -B -m unittest discover -s tests -p 'test_*.py' -v
```

검토 API 테스트는 실제 DB를 읽기 전용으로 복사한 별도 임시 SQLite에만 씁니다. HTTP 테스트도 임시 DB와 운영체제가 배정한 임시 로컬 포트로 실행합니다.
