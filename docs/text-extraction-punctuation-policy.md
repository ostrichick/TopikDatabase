# TOPIK 문자 추출 공백·문장부호 품질 규칙 (2026-10-09)

이 문서는 앞으로의 TOPIK 시험지·정답지·듣기 대본 추출에서 반드시
점검할 **지속적인 품질 게이트**다. Python 구현은
`src/extraction_rules.py:normalize_punctuation_spacing_v3`,
신규 36회 파생본은 `src/punctuation_pipeline_v6.py`가 기준이다.

## 검사 항목

1. 한국어 문장이 이어질 때 마침표 `.`, 쉼표 `,`, 물음표 `?`,
   느낌표 `!`, 콜론 `:` 뒤의 **누락된 한 칸 공백**을 확인한다.
   기존 공백·개행·탭은 유지하고 중복 공백을 만들지 않는다.
2. 공통 지시문 `어디입니까?<보기>`는 `어디입니까? <보기>`처럼
   `<보기>` 앞에 공백을 넣는다.
3. 듣기 대본 발화자 표기 `남자 :안녕하세요`, `여자 :________`,
   `여자 :(놀란 듯이)`는 콜론 뒤 공백을 넣되, 대본 발화자와
   대사/빈칸을 삭제하거나 결합하지 않는다.
4. `12:30`, `3.14`, `1,000`, 코드/식별자·숫자 표현,
   이메일·URL·도메인·파일 경로 및 확장자, 말줄임표 `...`와 `…….`,
   연속 문장부호 `?!`는 **문장 경계로 잘못 분리하지 않는다**.
   애매한 `:`·`?`·`!` 사용은 자동 수정 대신 원본 PDF 페이지를 확인한다.
5. 문제 본문·선택지·공통 지시문·공통 지문·듣기 대본 등 **모든 표시/저장 필드**를 검사한다.
   보존해야 할 `raw_question_text`, 원본 PDF·MP3, 정답·배점·이미지·파일 해시는 절대 수정하지 않는다.
6. 동형 대본을 공유하는 문항(36회 25/26·27/28·29/30)은 교정된 대본도 정확히 일치해야 한다.

## 버전 및 승인/적용 원칙

- 35회 역사적 정규화 `punctuation-space-v1,image-pure-v1`와
  원본 SQLite/PG 감사 해시, 기존 승인·검수 이력은 **불변**이다.
  누락 공백은 신규 v3 표시 파생값으로 보여주고, 원본 DB를 자동 덮어쓰지 않는다.
- 36회 v4·v5 역시 동결한다. 새 교정본은 `pdf-first-36-v6`,
  `punctuation-space-v3` 및 `staging-v6.json`으로 별도 생성한다.
  배포 전에 원본 데이터 SHA, 원본 페이지, 변경 필드/공백 수,
  전체 불변 필드, 입력과 출력의 한 글자 단위 diff를 검증한다.
- 기존 사람 검수 승인·메모가 있는 상태에서는 배치 UPDATE를 자동 실행하지 않는다.
  새 DB 교정은 별도 마이그레이션 키·원자적 사전 조건·백업과 독립 복원
  테스트가 있어야 하며, 승인된 텍스트의 변경을 별도로 검토해야 한다.
- 교정 전에 열려 있던 검수 탭이 새 텍스트를 저장해 되돌리지 않도록
  source revision marker를 review version에 반영하고, 구버전 탭은 409로 거절한다.
- 신규 추출기는 지원하는 버전별 정규화 품질 게이트를 통과하지 못하면
  import를 차단한다. 규칙을 고치면 기존 버전을 재작성하지 말고 새 버전·테스트·diff를 추가한다.

## 재현 명령

프로젝트 루트:

```powershell
py -3 -B -m src.pdf_ingest_36
py -3 -B -m unittest tests.test_punctuation_pipeline tests.test_punctuation_pipeline_v6 tests.test_import_exam_staging -q
```

현재 36회 v5→v6 대조: **432개 표시 필드**, **33개 필드 변경**,
**109개 공백 삽입**(공통 지시문 3, 듣기 대본 106).
직접 원본 PDF에서 독립 추출한 109개 위치의 문맥과 모두 일치함을
확인했다. 한국어 **어절 간 공백 전체**는 이 문장부호 규칙의 범위 밖이며
필요할 경우 별도로 사람이 원본과 대조해야 한다.
